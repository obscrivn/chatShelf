# Architecture

`src/index.ts` is the only engine/public DTO boundary. It accepts serialized JSON and keeps imported records private. The parser supports arrays, single mapping records and conversations envelopes; it follows current_node parents, validates node IDs/authors, rejects broken ancestry/cycles and accepts only plain-text user evidence. User-turn boundaries survive parsing. Identical active turn arrays sharing a conversation ID count once; different arrays quarantine that ID. Unsupported/invalid records abstain; file/JSON/size errors return fixed status codes. Mixed valid/invalid records can yield a partial library without per-record diagnostics to avoid raw leaks.

Classification uses the fixed catalog of four topics and one task per topic. Per-topic binary cosine and two distinct vocabulary hits avoid competition between unrelated topics; unknown tokens add no evidence. Task evidence requires topic words plus a task verb in an affirmative clause within a single user turn. Negated, quoted and hypothetical clauses abstain. Sensitivity screening runs first on all active user text. This is a conservative heuristic, not semantic understanding; see RELEASE_NOTES.md for measured weaknesses.

Aggregation counts distinct accepted conversation IDs once per topic/task. At least two IDs are needed for recurrence. Public output consists only of catalog enums/static guides, counts and fixed statuses. IDs/titles/filenames/raw text never enter output. No raw parser type is exported.

`src/ui.ts` imports only that entry point, builds DOM with textContent, clears file input values and uses a generation counter to cancel stale imports. Clear/pagehide remove visible state; reload requires reimport. JS garbage collection does not provide secure erasure. `src/shell.html` and `src/style.css` retain the approved bookshelf design.

Build-time TypeScript/esbuild bundle one inline script/style into release/ChatShelf.html with hash-based restrictive CSP (default/connect/worker/object sources none). No runtime libraries, external assets, persistence, telemetry or network calls. `scripts/package.mjs` writes SHA256SUMS. tests/engine.test.mjs covers parsing/classification/privacy/recurrence, tests/artifact.test.mjs checks the actual built HTML, and tests/browser-harness.ts builds a synthetic-only page excluded from release assets. Metrics JSON is regenerated by tests; its original corpus is exposed regression data. Strict quality gates and the authorized documented-limitations release route are separate commands.
